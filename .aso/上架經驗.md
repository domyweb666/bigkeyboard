## 一、三次退件各學到什麼

### 2.1 Information Needed：第一次送審幾乎一定會收到

- 這是制式要求，茄記同一週也收到同一份。要交兩樣：**最新 iOS 真機錄影**＋**審查備註六項**（用途與受眾、設定步驟與主要功能、外部服務、地區差異、受管制或第三方內容、帳號流程）。
- 錄影要從主畫面點開 App 開始，錄到每個主要功能，含付費和「回復購買」。
- 錄影前先自己跑一遍：豆鍵第一支錄影「回復購買」失敗、有幾款主題還顯示價格，跟備註寫的「7 款都買過」對不上，差點送出去。
- 準備錄影時不要刪 App 重裝，字典會清空。
- 範本：`.vibe/審核回覆-2.1.md`（豆鍵）、`E:\茄記\qieji-app\.vibe\審查回覆-2.1-2026-11-06.md`（茄記）。

### 4.4.1 鍵盤擴充：App 裡的一句話就能讓你被退

- 鍵盤程式本身沒問題，沒開完全取用也能打字。被退是因為 App 字典頁的黃卡寫「iOS 規定要開這個開關」，跟審查備註的「Full Access is optional」打架。
- **審查員看的是 App 畫面上的字，不是你的備註。** 鍵盤類 App 只要畫面上出現「必須開完全取用」的意思，就會被 4.4.1 退。
- 改法：黃卡標題改成「想讓豆鍵自動學詞？」，第一句寫明不開也能打字；使用說明加「不開完全取用也能用」一段。再錄一支完全取用**關著**的影片附上。

### 2.1(b) 內購一直轉圈：審查環境跟你的手機不一樣

- 審查員用 **iPad** 審 iPhone 限定的 App（相容模式），而且 StoreKit 在審查環境可能一直不回。
- 我們的 TestFlight 在 iPhone 上看得到價格，所以商品 ID、合約都沒錯，錯在程式沒處理「Apple 不回」。
- 規則：**所有 StoreKit 呼叫都要有時限**（價格 10 秒、重試一次；購買紀錄 10 秒），時間到改顯示「點一下重試」。購買紀錄沒讀完，不能當成「沒買」把主題換回免費款。
- 回覆時要寫清楚：找到的原因、哪個 build 修了、怎麼測。範本：`.vibe/審核回覆-2.1b.md`。

### 三次退件共同的教訓

- **iPad 一定要測。** 三次裡有兩次審查員用 iPad。豆鍵只做 iPhone，但審查照樣用 iPad 跑。
- **「完全取用關著」「沒網路」「沒買過的帳號」這三種狀態，送審前都要在真機各走一遍。** 開發時手上的機器通常三樣都是開著或買過的。
- 被退不用慌，大多是「要資料」或「說法不一致」。先讀退件附的截圖，找審查員實際看到哪個畫面。

## 二、版本號與送審流程

- **先確認哪一版已上線，再決定版本號。** repo 裡的紀錄常落後於後台，多米會在後台或別的 session 直接送。已通過的版本號不收新 build，緊急修復通常是 x.y.z+1。（11/16 照舊紀錄以為 1.1 還是草稿，把修復編成 1.1 build 81，白做一次。）
- 取消的版本草稿可以改名沿用：後台的 1.1.1（DEVELOPER_REJECTED）直接改名成 1.2。
- 小版號（1.2 → 1.2.1）App 內的「新功能」卡片不跳；中版號（1.1 → 1.2）才跳。
- 上傳後 Apple 要 5～10 分鐘處理 build，變 VALID 之前選不到。
- 加速審核只收「純修 bug」的版本。混了新功能的不一定收。
- 送出後才發現文案錯：`asc_release.py --withdraw --submit <build 號>`，先撤回、等版本變回可改、寫文案、再送。

### 送審前最後一關：新功能說明每一條都要有真機回報

- 1.2.1 寫了「登入頁的 email 欄現在叫得出豆鍵」，根據只有多米一句「功能都 ok」。送出後多米才說那一欄只有系統鍵盤能用，只好撤回重送。
- 問法要一題一項，選項寫「有修好／沒修好／沒測」，不要夾在長訊息最後。沒有明確回報的修正不寫進文案。
- 模擬器重現不了的問題（例如登入頁鍵盤）尤其要問。事實：iOS 在有密碼自動填寫的帳號欄只給系統鍵盤，第三方鍵盤輪不到，模擬器上卻輪得到。

## 三、文案規則

- **描述、推廣文字、新功能說明不放注音符號和聲調符號**，上架後會不見。要秀注音放截圖裡。`check_copy.py` 會擋。
- **後台不收「▌」「⌄」這類符號。** 段落標題用【】，項目符號用「•」，路徑用「>」。
- **審查備註上限 4000 字。** 1.1 的備註就占 3353 字，每版往前加段落很快就爆。`asc_release.py` 會先拿掉上一版加的段落（`DROP_NOTES_FROM`）、寫入前印字數，超過就停。
- **每次改版先列這版新增的連網、權限、資料去向**，對一次描述的隱私段和隱私權政策。1.1 加了 iCloud 同步，頁面上還寫「沒有任何連網功能」。
- **寫新功能說明前讀 `App/Veggie/WhatsNew.swift` 和這版的 git log**，不要照產品定稿寫。定稿會落後：1.1 拿掉英文工具列，英文建議字跟著沒了，定稿沒寫。
- 拿掉的功能，描述裡提到它的句子要一起改。1.2.1 拿掉首次設定流程，描述【開始使用】那句「第一次打開會帶你去設定」要跟著改。
- 審查備註不提其他手機系統和品牌（避開 2.3.10）。

## 四、ASO（搜尋排名）

- **關鍵字欄位要實搜過才寫。** 1.0 放了「ㄅㄆㄇ」，實搜前十名全是兒童學注音。「注音」單一個字、「ㄅㄆㄇ」在台灣店面是學注音的意圖，鍵盤類不放。
- 名稱裡有「注音鍵盤」，搜「注音鍵盤」還是排不進前 12，前面的對手評分數只有個位數到幾十。**字齊了還排不上，先查是不是缺下載和評分，不要急著改名稱。**
- 品牌字串定一個對外統一的寫法（「豆鍵注音鍵盤」），品牌搜尋各種寫法都排第 1。
- 英文（英國）語系值得做，多一組關鍵字欄位。英文語系沒有自己的截圖組時沿用繁中。
- 上架頭兩週不投 Apple Ads，先看自然量。
- 還沒做完的閘門：iPhone 實搜、新的眼睛看截圖、隱私標籤在後台對一次（見 `閘門紀錄.md`）。

## 五、用 API 寫後台（`asc_push.py`、`asc_release.py`、`asc_screenshots.py`）

做法：App Store Connect API 金鑰放 GitHub secrets，用工作流程跑。寫完一定讀回來逐欄比對，有一欄不對就失敗。

撞過的地雷：

- **新增 App 資訊語系時，Apple 會順手建同語系的版本語系。** 先重讀再決定 PATCH 還是 POST，不然會重複建立失敗。
- **自動建的英文語系缺支援、行銷、隱私權政策網址**，要照繁中補。
- **截圖一組最多 10 張。** 舊 6 張加新 9 張放不下，要先清空再傳（草稿版本暫時空著不影響架上版本）。傳完要等 Apple 處理完成、排順序、讀回比對。
- **新建版本時，Apple 會沿用上一版的描述、關鍵字、截圖**，缺的語系照上一版補。
- **審查備註一律從「上一個上架版本」組**，不要從草稿現有的備註接：草稿可能留著取消版本（1.1.1）加的段落。
- 描述跟定稿差太多（超過 4 行）就停，先查原因，避免把舊稿蓋回去。
- 審查聯絡人資料從上一版帶，不印到 log。
- 預設不選 build、不送審。要送才加 `--submit <build 號>`，而且文案比對全對、build 處理完成才會送。**送出去收不回，只能撤回。**
- 從工作分支手動執行工作流程、填 build 號就能送，不用另外推 `asc-release` 分支。
- 推分支觸發的工作流程，commit 訊息帶 `[skip ci]` 就不會跑。
- 工具沒讀也沒設「通過後自動上架或手動上架」，沿用後台原本的設定。

## 六、打包（TestFlight）

- build 號＝GitHub Actions 的 run 編號，不用手動加。
- 連推多次只編最後一次（`concurrency` 取消前一個），省 macOS 分鐘數。
- 編之前先跑 SwiftFormat、SwiftLint，不過就不編。
- 金鑰先自檢：直接問 Apple 一次，印出這把金鑰看得到哪些 app。金鑰要是 Team Key、角色 Admin。
- **私有 repo 的 Actions 額度會用完**（訊息 `Actions budget is preventing further use`），11/16 卡過一次，多米調高預算才恢復。打包卡住先查這個。
- macOS 機器排不到時訊息是 `The job was not acquired by Runner of type hosted`，沒開始跑不計分鐘，等 githubstatus 恢復再觸發。

## 七、下一個 app 第一次送審前的清單

照這份做，應該能省掉豆鍵 1.0 那三輪退件：

1. 付費合約、銀行、稅務先簽（要 1～3 天），順便申請小型企業方案（抽成 15%）。
2. 有內購：第一個內購項目要跟 App 新版本一起送；一定要有「回復購買」；價格從 Apple 拿，不寫死；**StoreKit 呼叫全部加時限和重試**。
3. 鍵盤或其他擴充：App 畫面上任何地方都不能讓人以為某個權限是必開的。
4. 真機錄影先錄好（從主畫面打開 App 開始），審查備註六項先寫好，第一次送審就附上。
5. 送審前在真機各走一遍：權限關著、飛航模式、沒買過的 Apple 帳號、**iPad**（沒有就用雲端模擬器）。
6. 描述、新功能說明跑一次文案檢查：不放注音、不放後台不收的符號、隱私段對得上這版的實作。
7. 隱私權政策網頁先上線，App 隱私標籤跟實作對一次。
8. 關鍵字先實搜再寫。
