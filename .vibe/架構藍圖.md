# 架構藍圖（鎖定基準）

流程圖：`.vibe/ios-keyboard-flowmap.html`（待掛點版，16 節點、25 邊）。
依據：`.vibe/產品定稿.md`。

## 白話走讀

你的鍵盤是這樣跑的：

1. **你在任何 app 點了輸入框**，iOS 把你的鍵盤叫出來。如果那是密碼欄，系統直接換回原生鍵盤，我們不管。
2. **鍵盤載入**：先把自己撐到三星那個高度（iOS 26 仍會在我們底下另加一排系統的地球／麥克風，所以我們的高度要扣掉它；地球鍵由系統提供，我們不畫），讀上次停在哪個模式（預設注音），把注音引擎跟詞庫叫進記憶體。
3. **四張鍵面擇一顯示**：注音、英文、符號頁、數字鍵盤。按「中文／ABC／!#1／123／符」這幾個鍵就在四張之間換。
4. **按任何一個鍵**：手指按下的瞬間跳出放大泡泡；放開時判斷是點一下還是長按。
   - 長按 → 送出鍵帽右上角那個小符號。
   - 點一下模式切換鍵 → 換鍵面。
   - 點一下英文／符號／數字鍵 → 字直接進輸入框。
   - 點一下注音符號 → 進「組字」。
5. **組字**：你按的ㄅㄆㄇ一個一個丟進組字器。組字器判斷接不接得上（ㄓ後面接ㄅ不合法就忽略那一下）。
6. **引擎算候選字**：合法的注音串交給引擎＋詞庫，算出「你 妳 擬 尼…」依機率排好，顯示在工具列那排。
7. **選字**：點候選字、或按空白鍵選第一個，字進輸入框，注音串清空，回到鍵面。
8. **刪除鍵**：注音還沒送出 → 只刪最後一個注音、候選字重算；注音是空的 → 刪輸入框裡的字。

## 專案分成哪幾塊

| 區塊 | 負責什麼 | 規劃中的檔案 |
|---|---|---|
| 建置與發布管線 ⚠ | 沒有 Mac。Windows 推上 GitHub → GitHub Actions（macOS）用 App Store Connect API 金鑰自動簽章、編譯、上傳 TestFlight → iPhone 從 TestFlight 安裝。金鑰只放 GitHub Secrets。 | `.github/workflows/testflight.yml`、`ExportOptions.plist` |
| 容器 app | 只有一頁，教使用者去「設定 → 一般 → 鍵盤」把鍵盤加進來。沒有別的功能。 | `App/` |
| 鍵盤殼 | iOS 叫起鍵盤時的入口；設高度；把字送進輸入框；記住目前模式 | `KeyboardExtension/KeyboardViewController.swift` |
| 版面 | 四張鍵面的鍵位表（哪個位置是哪個鍵、長按出什麼）＋三星配色尺寸 | `Layout/BopomofoLayout.swift`、`EnglishLayout.swift`、`SymbolLayout.swift`、`NumpadLayout.swift`、`SamsungTheme.swift` |
| 鍵的畫法 | 單一鍵的外觀、按下泡泡、長按判定 | `Views/KeyView.swift`、`KeyPreviewBubble.swift` |
| 候選字列 | 工具列那排：有候選字時顯示候選字 | `Views/CandidateBar.swift` |
| 組字器 ⚠ | 注音怎麼拼在一起、合不合法 | `Engine/BopomofoComposer.swift`（包小麥注音的 C++ `Mandarin` 組字器，MIT） |
| 引擎＋詞庫 ⚠ | 注音串 → 候選字排序 | `Engine/InputEngine.swift`（包小麥注音的 C++ `gramambular2`＋`McBopomofoLM`，MIT）＋ 小麥詞庫編譯出的 `data.txt`。Swift 與 C++ 之間用一層 Objective-C++ 橋接（`Engine/Bridge/`） |

## ⚠ 危險方塊（黑箱驗不全，動它要特別小心）

- **n11 組字器、n13 引擎＋詞庫**：這兩塊是借來的開源引擎。危險不在於碰錢或刪資料（本專案完全不連網、不碰使用者資料），而在於**它們是你最怕的「候選字選不到」的根源，而且你驗不全**——你只能驗「我常打的那些字出不出得來」，驗不了整本詞庫。規矩：這兩塊的程式碼**不准自己改寫**，只准「包起來用」；詞庫品質以開源專案為準；真的選不到字，第一步是換詞庫版本，不是改引擎。
- **建置與發布管線**：它碰的是 Apple 開發者帳號的 API 金鑰（放 GitHub Secrets，絕不進 repo）與對外上傳。你驗得了「有沒有通」，驗不了「金鑰有沒有外洩」——所以規矩：金鑰只存在 Secrets，程式碼與日誌裡不准出現；repo 保持私有。
- 外部開源碼進來時，要確認授權（MIT／BSD 可以直接用；GPL 類要停下來問）。

本專案的鍵盤本體沒有碰錢、碰真實資料、刪東西、對外連線的節點；唯一對外連線是管線上傳到 Apple。「允許完全取用」不開，引擎詞庫全放本機。

## 哪些區塊互相獨立（給之後判斷能不能平行做）

- **四張鍵面的鍵位表**彼此獨立：改注音鍵位不動英文鍵位，改符號頁不動數字鍵盤。
- **版面／鍵的畫法／候選字列**（畫面層）與 **組字器／引擎**（引擎層）互相獨立：畫面只負責「哪個鍵被按了」和「把候選字顯示出來」；引擎只負責「注音 → 候選字」。中間只靠兩個很窄的接口：「送一個注音進去」「拿一串候選字出來」。
- **容器 app** 跟鍵盤 extension 完全獨立。

不獨立的：`KeyboardViewController` 是殼，每一塊都會碰到它；改模式切換邏輯會同時影響四張鍵面。

## 鎖定聲明

此圖與此文為基準。AI 任何架構改動——新增區塊、改接口、換引擎、把畫面層跟引擎層混在一起——都不得偏離。要偏離，先回來改這份藍圖與 flowmap，經使用者確認後才能動程式。

實作出程式碼後，由 vibe-health-check / vibe-integrate 重跑 flowmap 掛點模式，把「規劃中的檔案」換成真實檔案並建立 file_index。
