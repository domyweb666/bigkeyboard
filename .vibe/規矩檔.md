# 規矩檔（AI 每次動工前必讀）

## 通用 AI 行為基準（從專案第一天起就成立，勿改）

1. **不准猜假設，不確定就問。** 收到任何指令，若有不明確的詞、有多種可能的解讀、缺少關鍵資訊——**停下來把不明確的地方列出來問使用者**，不要替他選一個解讀就動手。靜默的假設是這套系統最大的失敗源頭。

2. **每一行改動都必須能追溯到使用者的明確要求。** 不准順手「改進」相鄰的程式碼、不准重整不相干的格式、不准刪掉「看起來像死碼」但不在這次任務範圍內的東西、不准做沒被要求的重構。每一行 diff 都要對得上一句使用者講過的話。

3. **不准加沒被要求的功能、抽象、設定項、錯誤處理。** 「想說以後可能會用到」「順便寫得更彈性一點」「加個 config 比較好」——全部不准。要做的事跟使用者要的事一對一，多的一律砍。

## 使用者的流程選擇（2026-11-01）
- 使用者明確要求：片 5 起不逐片驗收，一次做完所有功能（到片 13）後再由他整體測試、回報修正。AI 照做，每片仍寫標準清單進 .vibe/，最後彙整成一份總測試清單。能在雲端用真詞庫測的引擎邏輯一律先測。
- GitHub Actions 免費額度已耗盡（macOS runner ×10 計費）。使用者需自行設定 Actions 預算；在那之前推上去的 commit 不會產生 build。

## 專案特定規矩（vibe-voice-lock 立規）

### 判斷層（AI 的腦怎麼想）
- 語言只有 Swift，UI 只用 UIKit（鍵盤 extension）＋ SwiftUI（容器 app 那一頁）。不准引入 Flutter、React Native、Objective-C、第三方 UI 框架。
- Feature-First：每片只做切片帳本裡那一片。沒被要求的 protocol、generic、manager、service、coordinator 一律不准。
- 新檔案模仿鄰近檔案的寫法。一個專案裡只准有一種做同一件事的方式。
- 不准引入架構模式（MVVM、VIPER、Redux、Combine 管線）。鍵盤是「按鍵 → 殼 → 輸入框」三步，就寫成三步。
- 畫面層與引擎層只靠兩個接口溝通：`feed(注音符號)`、`candidates() -> [String]`。畫面不准碰引擎內部，引擎不准碰 UIKit。
- 外部套件只准放引擎層（組字器、斷詞引擎、詞庫）。畫面層零外部依賴。
- 鍵位表是資料（陣列），不是程式邏輯。四張鍵面各一份資料檔，渲染程式只有一份。
- 中文註解、中文 commit 訊息。識別字用英文。

### 可驗證層（機器檢查，不靠 AI 記得）
- 沒有 Mac，pre-commit hook 跑不了 Swift 工具，所以強制點放在 CI：GitHub Actions 在編譯前跑 SwiftFormat（lint 模式）＋ SwiftLint，不過就不編、不上傳。規則檔：`.swiftformat`、`.swiftlint.yml`，從第一片起就在。
- 本機（Windows）的 pre-commit hook 只做兩件不需要 Swift 工具的事：擋住 `.p8`、`*.mobileprovision`、`*.p12` 進 repo；擋住檔名含 secret／key 的檔案。

## 踩過的坑・不准再犯（vibe-no-repeat-error 自動回灌）

- 【片1】Apple 現在只收 Xcode 26（iOS 26 SDK）編的 build；workflow 第一步一定要 xcode-select 到 Xcode_26*。
- 【片1】build 號要靠 Info.plist 的 CFBundleVersion 明確接 $(CURRENT_PROJECT_VERSION)，並在 xcodegen 之前把 run 號寫進 project.yml；單靠 xcodebuild 命令列參數不會進 Info.plist，Apple 會以「版號重複」拒收。
- 【片1】雲端簽章的 API 金鑰必須是 Team Key、Admin、且勾「Access to Cloud Managed Distribution Certificate」；缺勾就 Cloud signing permission error，且建好不能補勾、要重建。
- 【片5】鍵帽不用 UIButton：iOS 輔助使用「按鈕形狀」開著會給所有 UIButton 文字加底線。用 UIControl＋UILabel。
- 【片5】小麥桌機版的組字器是「同類符號取代」，手機注音要的是「自動斷音＋可不打聲調」。這兩個行為放在橋接層（stage 判斷＋FuzzyToneLM），不改小麥的碼。詞庫裡「不要」的 key 是 ㄅㄨˊ-ㄧㄠˋ（變調），所以沒聲調一定要模糊比對才找得到。
- 【片3】iOS 26 對第三方鍵盤仍保留底部系統排（地球＋麥克風），needsInputModeSwitchKey 為 false、自畫的地球鍵會被藏；總高度要以「我們的區域＋系統排」合計去對三星比例。先前「第三方拿回整塊區域」的假設錯了。
- 【片3】雲端 runner 每次是新機器，自動簽章每跑一次產一張開發憑證，Apple 帳號上限 2 張，第 3 次起就「Choose a certificate to revoke」。解法不是改簽章身分（automatic 不准覆寫 CODE_SIGN_IDENTITY），是跑完用 ASC API 刪掉 displayName=「Created via API」的 DEVELOPMENT 憑證。已做進 testflight.yml 最後一步。
- 【片2】build 號 = workflow 的 run_number，不是 Actions 列表看到的 run id；回報使用者 build 號前先用 ASC 狀態查詢 workflow 確認。
- 【片2】swiftformat 的 --lint 要放在路徑後面。
- 【片1】macOS runner 的 pip 被鎖，要用 venv。
- 【片1】App Store Connect 裡沒有 app 紀錄就上傳會失敗；新 bundle ID 要先在 Identifiers 註冊再在 ASC 建 app。
