# 規矩檔（AI 每次動工前必讀）

## 通用 AI 行為基準（從專案第一天起就成立，勿改）

1. **不准猜假設，不確定就問。** 收到任何指令，若有不明確的詞、有多種可能的解讀、缺少關鍵資訊——**停下來把不明確的地方列出來問使用者**，不要替他選一個解讀就動手。靜默的假設是這套系統最大的失敗源頭。

2. **每一行改動都必須能追溯到使用者的明確要求。** 不准順手「改進」相鄰的程式碼、不准重整不相干的格式、不准刪掉「看起來像死碼」但不在這次任務範圍內的東西、不准做沒被要求的重構。每一行 diff 都要對得上一句使用者講過的話。

3. **不准加沒被要求的功能、抽象、設定項、錯誤處理。** 「想說以後可能會用到」「順便寫得更彈性一點」「加個 config 比較好」——全部不准。要做的事跟使用者要的事一對一，多的一律砍。

## 專案特定規矩（vibe-voice-lock 立規）

### 判斷層（AI 的腦怎麼想）
- 語言只有 Swift，UI 只用 UIKit（鍵盤 extension）＋ SwiftUI（容器 app 那一頁）。不准引入 Flutter、React Native、Objective-C、第三方 UI 框架。
- Feature-First：每片只做切片帳本裡那一片。沒被要求的 protocol、generic、manager、service、coordinator 一律不准。
- 新檔案模仿鄰近檔案的寫法。一個專案裡只准有一種做同一件事的方式。
- 不准引入架構模式（MVVM、VIPER、Redux、Combine 管線）。鍵盤是「按鍵 → 殼 → 輸入框」三步，就寫成三步。
- 畫面層與引擎層只靠兩個接口溝通：`feed(注音符號)`、`candidates() -> [String]`。畫面不准碰引擎內部，引擎不准碰 UIKit。
- 外部套件只准放引擎層（組字器、斷詞引擎、詞庫）。畫面層零外部依賴。
- 鍵位表是資料（陣列），不是程式邏輯。四張鍵面各一份資料檔，渲染程式只有一份。
- 中文註解、中文 commit 訊息。識別字用英文。

### 可驗證層（機器檢查，不靠 AI 記得）
- 沒有 Mac，pre-commit hook 跑不了 Swift 工具，所以強制點放在 CI：GitHub Actions 在編譯前跑 SwiftFormat（lint 模式）＋ SwiftLint，不過就不編、不上傳。規則檔：`.swiftformat`、`.swiftlint.yml`，從第一片起就在。
- 本機（Windows）的 pre-commit hook 只做兩件不需要 Swift 工具的事：擋住 `.p8`、`*.mobileprovision`、`*.p12` 進 repo；擋住檔名含 secret／key 的檔案。
