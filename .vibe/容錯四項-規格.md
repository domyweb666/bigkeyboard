# 容錯四項：連刪保護、簡拼、iOS 替代文字、鄰鍵容錯（2026-11-25 多米：四項都做）

背景與模擬數字在 `.vibe/JTBD對照-2026-11-25.md`。分支 `tolerance-1.3`（從 redesign-domy-sage 85119bd 開）。
動工前讀 `.vibe/規矩檔.md`。最高標準是手感：打字不能有可感知的延遲，打對的字不能被亂改。

## 共用規則

- 鍵位、尺寸、外觀都不動。不加設定開關。不做個人落點校正。
- 單檔 ≤ 400 行、函式 ≤ 50 行、class 本體 ≤ 250 行（SwiftLint）；SwiftFormat 寬 120，中文字算兩格；中文註解、英文識別字。
- 手感參數全部放 `SamsungTheme`，註明真機怎麼調。
- 不連網、不新增要完全取用的東西。

## 1. 連刪保護（Swift，只改鍵盤畫面）

- 只在 `KeyboardView.hitTest` 生效，滑動（`touchMoved`／slide）不套。計時用 `CACurrentMediaTime()`，hitTest 不准有副作用。
- 記「刪除串」：⌫ 每按一次 +1（按住連刪一次算 2 下），最後活動時間＝按下、連刪每一下、放開。按了別的鍵串歸零。
- 串 ≥ 1 且離最後活動 ≤ 0.6 秒：落點在 ⌫ 那格（鍵框各邊往外半個縫）就是 ⌫；注音「動態感應範圍」多吃的 10pt 這時不准吃進 ⌫。
- 串 ≥ 2 且 ≤ 0.6 秒：離 ⌫ 鍵框 14pt 內也算 ⌫（ㄥ 靠 ⌫ 的那一側、換行鍵的上緣）。
- 串 ≥ 2 且 ≤ 0.25 秒：放寬到 36pt（整顆 ㄥ、換行鍵上半）。換行鍵最要緊：在 LINE 連刪滑到會把訊息送出去。
- 所有鍵面都適用，鄰鍵用距離算，不寫死 ㄥ。落點照舊先往上修 `touchLiftPoints`。

## 2. 簡拼（引擎）

- 現況：只有最後一個音可以只打聲母（`FuzzyToneLM::expand` 的 completions）。要做到任何位置都可以：ㄒㄒ→謝謝、ㄉㄋㄠㄨㄨ→電腦玩物這種（內建 iOS 8 起就有；詞要在詞庫裡）。
- 可以省略的音：只有聲母、沒聲調；或只有介音（ㄧㄨㄩ）、沒聲調。sealed 一聲的不算。
- 逐音往下接，詞庫（和使用者字典）沒有那個開頭就丟。第一個音的「某聲母有哪些帶聲調的音」算一次就記起來；前綴展開結果要記起來，打下一個鍵不重算。
- 扣分：每省略一個音扣分，聲母自己不成音的（ㄅㄒ…）扣少、自己就是一個音的（ㄓㄔㄕㄖㄗㄘㄙ、ㄧㄨㄩ）扣多，數值用測試定。原本「只有最後一個音省略」的結果不准變差。
- 多音節的補全結果照分數最多留 100 個。rawValue 一律是實際查中的帶聲調讀音（學詞要用）。

## 3. iOS 替代文字（Swift）

- `requestSupplementaryLexicon`，每次叫出鍵盤在背景拿一次（不擋鍵盤出現），只留 `userInput != documentText` 的。新檔 `KeyboardViewController+Lexicon.swift`。不存檔、不學。
- 注音：組字中的注音（去空白、去 ˉ）等於某個輸入碼，而且 `pendingText` 是空的 → 該片語排候選第一個。空白、標點、換行、收鍵盤都照「第一個候選」送它；這時空白不當一聲，小字是「選字」。選它不學詞、不記接續，引擎清空。候選索引要對齊（後面的往後移一位）；長按它不跳「忘掉」選單。
- 英文／符號／數字鍵面：按空白時，游標前那串非空白 ASCII（整串）等於輸入碼（先比大小寫完全一樣，再不分大小寫）→ 換成片語再補空白。馬上按一下 ⌫ → 還原成原本打的碼（不含空白）；按了別的鍵就不能還原。標點、換行不觸發（換行可能是送出，太危險）。
- 同一碼多個片語：全排在前面。

## 4. 鄰鍵容錯（引擎＋Swift）

### 接口（兩邊照這個寫）

```objc
/// 同 feedSymbol:，多帶「這一下也可能是想按的鍵」和代價（越大越不可能，照手指落點算）。
- (BOOL)feedSymbol:(NSString *)symbol
     alternatives:(NSArray<NSString *> *)alternatives
            costs:(NSArray<NSNumber *> *)costs NS_SWIFT_NAME(feedSymbol(_:alternatives:costs:));

/// 候選裡哪幾個是修正出來的（照 candidates 的索引，遞增）。沒有為空陣列。
@property (nonatomic, readonly) NSArray<NSNumber *> *correctedIndexes;
```

原本的 `feedSymbol:` 留著（等於沒有 alternatives）。

### Swift

- 按下時照落點（先往上修）算鄰鍵代價：`base + 0.434/2 × [((p−鄰鍵中心)/σ)² − ((p−按到的中心)/σ)²]`，x、y 各用自己的 σ（σx ≈ 0.28 × 鍵距、σy ≈ 0.28 × 排距），下限 base。只留注音鍵、代價 ≤ 上限（約 4）的，最多 3 顆。base 先用 1.5，最後由引擎測試決定。
- 滑過去再放開的字不帶 alternatives。
- 修正的候選在候選列、展開的格子都要看得出來：字用 `SamsungTheme.accent` 色（常數獨立一個，好改）。VoiceOver 不用管。

### 引擎

- 每個注音鍵記一筆事件（符號、alternatives），跟格子、buffer 同步：收進格子、退格、`reopenLastReadingIfBufferEmpty`、sealFirstTone（多一筆 ˉ 事件）、選走前段、clear、`insertReading` 失敗都要對。
- 重排候選時：只換一個鍵。從目前組字中所有事件挑代價最低的最多 12 個替換，照 `feedSymbol` 同一套斷音規則重新斷音，用輕量 Viterbi（每個 span 只拿最高分那個詞）算整句分數，跟「照打的」同一把尺的分數比：`替換分數 − 代價 > 照打分數` 才算贏。替換的那邊不准用簡拼（最後一個音只打聲母除外）。只有聲調的音直接淘汰。
- 輕量查詢另開小快取（讀音→最高分的詞），不要塞爆原本的 cache_。
- 贏了而且 ≥ 2 個音：修正的整句放第 0 個，照打的整句放第 1 個，`defaultCandidateCount`：照打的是單一個詞 → 1（選回照打的會被學起來，下次就不會再改）；是多個詞串的 → 1 + 原本的。選修正的＝送整句、組字清空、`lastSelectedReading` 給修正後的讀音。
- 沒贏但差不到 1 分、≥ 2 個音：最多 1 個，插在引擎猜的後面。
- 只有 1 個音：不搶第一；代價夠低的最多 2 個字，插在第 3 格（索引 3）起。
- 已在候選裡的字不重複放（贏的時候例外：提到最前面）。
- 接續紀錄把整句提到最前面時，修正不搶第一，改成「插在引擎猜的後面」。
- 選走前段（span < 全部）之後剩下的照樣能修正。

## 測試（引擎在這台 Windows 就能編）

- VS BuildTools 的 cl 在 `C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools`（先跑 vcvars64）。C++ 核心（FuzzyToneLM、斷音、修正搜尋）搬到 `KeyboardExtension/Engine/Bridge/` 的純 C++ 標頭，`.mm` 只留接口；Vendor 一行都不改。Windows 測試用的 MemoryMappedFile 替身放 scratchpad，不進 repo。
- 詞庫要用 LF 版：`git show HEAD:KeyboardExtension/Resources/mcbopomofo-data.txt > 檔案`（工作目錄是 CRLF，會查不到字）。
- 要有數字：
  1. 回歸：`.vibe/*.md`、`.aso/*.md` 抽 500 句 4～10 字（做法照 JTBD 對照的模擬），打聲調、不打聲調各跑一次，沒有 alternatives 時第一候選跟改之前一模一樣的比例（要 ≥ 99.5%；不一樣的列出來看是不是變好）。
  2. 簡拼：常用 2～4 字詞全打聲母，想要的詞在前 1／3／8 的比例；ㄒㄒ 有謝謝。
  3. 容錯：落點用常態分布（σx 8、10、12pt，鍵距 35.5）模擬打字，比較「沒容錯／有容錯」整句對的比例，和「全打對卻被改」的比例（≤ 0.5%）。用這個定 base、上限、margin。
  4. 速度：20 個鍵的長句逐鍵打，每鍵平均、最慢，改前改後都量；改後最慢不能超過改前 + 3 毫秒。
  5. 狀態：退格、reopen、sealed 一聲、選前段、清空後事件跟格子一直對得上（加隨機操作的檢查）。

## 做完的結果（2026-11-25）

- 定下來的數值：鄰鍵代價 base 2.5、上限 4、σ 0.28、最多 3 顆；贏的門檻 0、「差不到」1 分；單音代價 ≤ 3.5、最多 2 個。簡拼扣分：聲母 1、自己成音的 3（同一串裡有聲母省略時 2），自己成音的省略最多留 8 個。
- base 2.0 會多救 5～8 個百分點，但不在詞庫的人名被改的比例升到 0.85%，所以取 2.5。真機覺得救太少再往下調。
- 跟規格不同：(1) 打了聲調但不存在的音，換成代價最低、存在的鄰鍵，直接改組字中的注音、不上色（`ComposingSession::insertRescued`）；以前是整個音消失。(2) 舊錯順手修：打 ㄈ 再打 ㄧ 會刪掉前一個音，因為試放失敗後照樣刪；引擎重寫時碰到同一段。(3) 詞庫直接讀檔，不經 `ParselessLM`。
- 打包前獨立審查（11-25 下午）修了三條：
  - 學過的詞碰上看不出是不是簡拼的音（ㄓㄔㄕㄖㄗㄘㄙ、ㄧㄨㄩ）不給滿分，當成 -5（`kGuessedUserScore`）。修之前學過「炒飯」，打 ㄨㄛ ㄔ ㄈㄢ 會出「我炒飯」。帶 300 個、1500 個學過的詞跑回歸，第一候選跟 1.2.3 一樣的比例從最低 99.0% 變 100%；簡拼、只省最後一個音的數字沒變，容錯救回率沒變差。
  - 替代文字：輸入碼和片語只差大小寫的丟掉（代決）。系統給的清單混著常用詞和聯絡人。代價是使用者自己加的「usa → USA」也不會換；要改回去，`TextReplacements.init` 的 where 拿掉 `lowercased()`。
  - 單音的修正字插在引擎猜的後面（`addSingleCorrections`），不再插進接續紀錄提前的那幾個字中間。
- 舊錯，1.2.3 以前就有，2026-11-26 修了（分支 overnight-20261126-1104）：數字表情（1️⃣）在候選裡被當成三個音，組字中選它會多吃後面的音。`CandidateList::append` 改照格子裡的讀音數；引擎測試 `span` 修正前 48 個全錯、修正後 0。
- 已知弱點：一段組字只救一個鍵；ㄈㄧㄥ（想打 ㄌㄧㄥ）救不回來；ㄉㄨ、ㄋㄨ 這類會黏成一個音，簡拼打不到；兩字詞的順序照詞頻（ㄒㄒ 的謝謝排第 8）。
